# Recover a program, then watch your edit

[c64-bars.a](c64-bars.a) is a 38-byte C64 program. It paints horizontal colour
bands by reading the raster position and writing a colour from an eight-byte
palette. Recover its source, rebuild it unchanged, then alter one operand and
see a different palette in Emu198x.

| Original | After changing the XOR mask |
|---|---|
| ![Original raster bars](c64-original.png) | ![Recoloured raster bars](c64-changed.png) |

These are PAL captures from Emu198x, running the commands below.

## Build and recover

Run from the Asm198x repository root. Build `asm198x` and create a fresh output
directory; recovery refuses to overwrite an existing source file.

```sh
cargo build -p asm198x
mkdir -p target
c64_demo=$(mktemp -d target/c64-bars.XXXXXX)

target/debug/asm198x -d acme examples/recovery/c64-bars.a -o "$c64_demo/original.bin"
target/debug/asm198x -d acme --prg examples/recovery/c64-bars.a -o "$c64_demo/original.prg"

target/debug/asm198x disasm --recover -d acme --org 0x2000 \
  --code 0x2000:0x201e --data 0x201e:0x2026 \
  --label 0x201e:palette --label 0xd011:display_control \
  --label 0xd012:raster --label 0xd020:border \
  "$c64_demo/original.bin" -o "$c64_demo/recovered.a"

target/debug/asm198x -d acme "$c64_demo/recovered.a" -o "$c64_demo/rebuilt.bin"
target/debug/asm198x -d acme --prg "$c64_demo/recovered.a" -o "$c64_demo/rebuilt.prg"
cmp "$c64_demo/original.bin" "$c64_demo/rebuilt.bin"
cmp "$c64_demo/original.prg" "$c64_demo/rebuilt.prg"
```

Both comparisons should be silent. Recovery reads the **raw** 38-byte image.
`--prg` wraps the same bytes with the two-byte little-endian load address
`00 20`, making a 40-byte file for the C64 loader. Feeding that header to raw
recovery would shift the instructions and addresses.

The code is `$2000`–`$201D`; the palette is `$201E`–`$2025`. Range ends are
exclusive. The recovered loop is `l_2006`, and its paint subroutine is
`l_2018`. The supplied register and palette names describe addresses we know;
they were not stored in the binary.

## Run the recovered program

Use a UI-enabled `emu198x-c64` build and your C64 firmware directory containing
`kernal.rom`, `basic.rom`, and `chargen.rom`. In the family checkout, build the
emulator with `cargo build -p emu198x-c64` from `Emu198x/emu198x` if needed.
Set these paths for your installation; the following match the family layout:

```sh
c64_emu=../../Emu198x/emu198x/target/debug/emu198x-c64
c64_roms=../../Emu198x/roms/c64

"$c64_emu" --rom-dir "$c64_roms" --model pal --load "$c64_demo/rebuilt.prg"
```

At the `READY.` prompt, type `SYS 8192` and press Return. The PRG loader imports
the program; `SYS` starts execution at `$2000` (8192 decimal). Coloured bands
replace the BASIC screen. Close the emulator window to leave the program.

## Change one byte

```sh
cp "$c64_demo/recovered.a" "$c64_demo/changed.a"
```

Open `changed.a` in that output directory and replace `EOR #$00` with
`EOR #$0F`. Save it, then assemble and launch:

```sh
target/debug/asm198x -d acme --prg "$c64_demo/changed.a" -o "$c64_demo/changed.prg"
cmp -l "$c64_demo/rebuilt.prg" "$c64_demo/changed.prg"
"$c64_emu" --rom-dir "$c64_roms" --model pal --load "$c64_demo/changed.prg"
```

`cmp` should report one difference at byte **28** (one-based, including the
PRG header), from octal `0` to `17`, and exit with status 1 because the files
differ. Type `SYS 8192` again. The band positions stay the same; their colours
change because XOR flips the four bits of each colour index. This changes
palette indices, not RGB brightness: C64 colours are not a brightness scale.

## Capture the result without a window

The included [startup script](c64-start.json) types `SYS 8192` after import.
These commands also work with an emulator built using `--no-default-features`.

```sh
"$c64_emu" --rom-dir "$c64_roms" --model pal --load "$c64_demo/rebuilt.prg" \
  --script examples/recovery/c64-start.json --frames 120 \
  --screenshot "$c64_demo/original.png"
"$c64_emu" --rom-dir "$c64_roms" --model pal --load "$c64_demo/changed.prg" \
  --script examples/recovery/c64-start.json --frames 120 \
  --screenshot "$c64_demo/changed.png"
```

## Why it works

`SEI` prevents the normal maskable interrupt handler from interrupting the
loop. Writing `$0B` to `$D011` clears display-enable bit 4, making the border
colour fill the picture. Reading `$D012` gives the low eight bits of the
current raster line. Five right shifts divide that value by 32, yielding a
palette index from 0 to 7. The paint subroutine applies the XOR mask and writes
the result to border-colour register `$D020`.

This is a polling demo, without cycle-aligned raster interrupts. A colour
change can land partway across a scanline, leaving a small step at a band
boundary. The palette repeats when the low raster byte wraps at line 256;
the capture intentionally uses PAL so its framing is reproducible. The
program assumes a normal C64 ROM boot and runs continuously.

Register meanings are documented in Commodore's *Commodore 64 Programmer's
Reference Guide* (1983), pp. 321–324 and Appendix N. The family source library
holds the [manual record](https://github.com/stevehill1981/198x/blob/main/reference/by-system/commodore-c64/1983-commodore-64-programmers-reference-guide.md)
and a [VIC-II synthesis](https://github.com/stevehill1981/198x/blob/main/syntheses/commodore-c64/vic-ii-screen-memory-modes-sprites.md).

# Canonical ca65 source reader (#795, #924)

The agreed approach is a full ca65 reader redesign above the existing shared
numeric grammar. The user selected this approach on 2026-10-21. The narrower
expression-prefix proposal in design.md is superseded. Neither rejected scalar
candidate nor file trial will merge.

The reader must consume authored and generated tokens through one ordered source
stream. Generated commas participate in directive grammar. Numeric expressions
use the existing shared operator grammar; names use the existing scope
environment; strings use TextSyntax/StringTokens. Preserve physical versus
generated token provenance. Do not introduce a second arithmetic parser, private
namespace, public AST break, or new dependency.

## Failure modes to carry into acceptance tests

- Splitting fields before expansion loses generated separators and suffix
  arithmetic: the retained 40-case native matrix passes on #920 and regresses
  in both rejected attempts.
- Expanding a complete line early moves query effects before preceding symbol
  reads; retain all source-order matrices from checked #920.
- Reducing selectors to one Expr loses names, actions and multiple fields;
  retain the 320 scalar and 200 file controls, including header constructors.
- Spelling-only identifier checks confuse physical register tokens with
  generated identifiers (#918, #923); retain provenance through expansion.
- Eagerly evaluating skipped or captured source changes lazy directive, name,
  include and effect behavior. Preserve the approved lexical admission rules.
- Re-reading generated bytes as physical quoted source corrupts opaque strings.
- Replacing the reader can lose macro/repeat capture boundaries, pending include
  order, source spans, scope bindings, deferred aliases and external metadata.
- Semantic early termination can truncate syntax-only formatting. Formatting
  must retain authored source, remain idempotent, and reassemble identically.
- Debug addresses must preserve physical offsets and logical absolute spans.

## Implementation sequence

1. Inventory reader entry points in ca65/mod.rs, ca65/project.rs, ca65_flat.rs
   and shared expression parsing. Map each binding decision and existing native
   fixture to its responsible seam before editing code.
2. Write a bounded token-stream contract with source provenance, expansion
   limits, capture boundaries and ordered consumption. Numeric parsing delegates
   to the shared grammar. Test delimiter and effect order against native tools.
3. Introduce the canonical reader behind private ca65 entry points. Migrate
   numeric, name, text, header and file consumers in separately checked slices.
   Preserve the existing resolver and scope environment. Do not merge a slice
   that reduces any checked #920 match.
4. Exercise syntax-only formatting separately from semantic execution, then
   macro/repeat/conditional/include and configured/flat paths together.
5. Require all retained native matrices, generated-field and token-provenance
   controls, formatter/debug/refusal/output-preservation invariants, full
   Rust/Lua/Clippy/Node checks, fresh 4510 replay and five native archive receipts.
   Mandatory package cohorts need omission and corruption controls.

The approach is approved; this document records constraints and sequence rather
than claiming unimplemented code is qualified. Finish independent #921 from
checked #920 before starting reader migration. If implementation requires a new
dependency or public breaking change, seek the separately required approval.

# Proposed ecosystem execution design (#618)

Extend the existing xtask ecosystem command and manifest. No dependencies, external service or upstream build-script execution are needed.

1. Keep schema 1 and its admission fields readable. Add optional, reviewed build plans to targets. A plan names ordered native and Asm198x argv steps, each step's working directory, timeout and stage (assembly/link/finalise), required tool version probes, output paths and exact artifact pairs. Tools are identified by resolved executable hash and captured version process. Old targets without a complete plan remain unknown; a lone assembler invocation never implies a complete build.
2. `ecosystem fetch` and `verify` remain inert. Add an explicitly invoked audit action taking an acquisition directory, a new result directory and an explicit target/all selection. Verify each full source commit and licence, then copy its tracked source into separate fresh native and Asm workspaces. Never edit the acquired tree or run its Makefile. Record any reviewed adapter and its hash. Reject source/output path escapes, symlinks escaping the workspace and reuse of result directories.
3. Run only the reviewed argv steps, with bounded process time, output and artifact sizes. Record commands, source/manifest/adapter/Asm revision hashes, executable identities, exit results, logs, artifact lengths/hashes, comparison results and the first failing stage. No shell interpretation. Exact final outputs define equivalence; intermediate objects from different toolchains are not comparable final artifacts.
4. Distinguish equivalent, reference-control failure, Asm rejection, post-assembly tool failure, artifact mismatch and infrastructure unavailable. Missing plans, tools, version mismatches, timeouts or unreadable source never count as compatibility successes. Carry linked issue references as evidence metadata. Only a successful fresh control permits an Asm compatibility verdict.
5. Generate the published table from retained result records, showing capture time, upstream and Asm revisions, tool identity, first boundary and evidence links. Freshness checks reject stale source/manifest records. Keep assembly equivalence separate from emulator/hardware validation. Replay captured reference artifact bytes in ordinary CI where their licence and size permit; prove known successes continue matching and include deliberate mismatch/missing-output controls.
6. Add a scheduled and manually dispatched runner using reviewed native tool installation. A release workflow can invoke the same audit explicitly; package publication stays governed by its existing qualification gate. Retain per-target artifacts even for failures. Unknown or reference failures remain visible and cannot silently reduce the denominator.

Implementation files: `xtask/src/ecosystem.rs` and focused private submodules if needed; `ecosystem/corpus.json`; retained result fixtures under `ecosystem/`; `docs/ecosystem-corpus.md`; a dedicated ecosystem workflow; existing CI for manifest/ledger/replay checks. First validate complete targets already admitted, then admit broader workloads with source pins and licences through focused reviews.

Alternative: replace the admission manifest with schema 2, moving every legacy target into the ordered-plan shape at once. This is cleaner on disk but breaks current manifest consumers and combines migration with runner implementation. The additive plan above is recommended.

The additive design was approved on 2026-10-16. Implementation follows the independent compatibility fixes. Existing acquisition remains inert.
